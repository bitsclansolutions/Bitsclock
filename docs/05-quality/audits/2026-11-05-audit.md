Scope: whole project (src/, prisma/, next.config.ts, package.json). Read-only; no code changed.
Specialists: security, breaker, scale, reliability, code quality, UX/accessibility, test strategy, dependencies (all 8 ran).
Known accepted risks: none (no risk register existed before this audit).
Verification: every High below was re-read in code by the lead auditor unless marked *needs checking*. Line numbers are the verified ones.

## Top 3

1. **RBAC privilege escalation** (H1): anyone given `users.manage` or `roles.manage` can become Administrator or take over the admin account.
2. **Data residency** (H2): employee personal data and time records live on Supabase, Upstash, and planned Vercel, outside JMTS-approved ecosystems (JMTS policy).
3. **Billing exports silently incomplete** (H3): detailed CSV/PDF and the detailed report stop at 2,000 rows with no warning while totals count everything.

## Systemic patterns

- **P1 No central "can this actor act on this target" rule.** Authorization checks the actor's permission but never the target's rank (admin user, Administrator role, actor's own role). Causes H1. Fix once: `assertCanManageUser(me, target)` / `assertCanAssignRole(me, role)` / `assertCanEditRole(me, role)` in `src/lib/roles.ts`.
- **P2 Read-modify-write on shared state without a condition or transaction.** Refresh rotation (M1), security resets (H4), last-admin guard (M9), reset-code attempts (L1), idempotency rows (M5), cache loader stale-write (M7). Habit: conditional `updateMany` (compare-and-swap) or one `$transaction`.
- **P3 Invariants enforced on some write paths only, not in the database.** 24 h cap skipped by timers (M3); one-running-timer, end>start only in app code; `TimeEntry.user onDelete: Cascade` (M11); billable self-set (M13).
- **P4 Single-instance assumptions on a multi-instance target.** In-memory cache invalidation, rate-limit buckets, 60 s session cache, fire-and-forget promises after response (M6, M7, M4).
- **P5 Silent caps and silent failures, no observability.** 2,000-row caps (H3, M15), CSV download failing silently (M22), email failures only `console.error`, no audit trail, no health check (M12).
- **P6 No test safety net.** All of the above can regress unseen (H11).

## High

### H1 [HIGH] [High confidence] [S] [Security] Delegated user/role admins can escalate to Administrator
**Where:** `src/app/api/roles/[id]/route.ts:49-51` (DELETE reassigns members to any role, including Administrator); `src/app/api/roles/[id]/route.ts:7-34` (PATCH: a `roles.manage` holder can edit their own role's permissions); `src/app/api/users/route.ts:42-52` (POST accepts any `roleId` and a caller-chosen password); `src/app/api/users/[id]/route.ts:28-47` (PATCH any user's role, email, password, admins included); `src/app/api/users/[id]/reset-password/route.ts:20-26` (works on admins).
**What:** `const target = await prisma.role.findUnique({ where: { id: reassignTo } }); ... updateMany({ where: { roleId: id }, data: { roleId: target.id } })` — no check that `target` isn't Administrator or that the caller is admin.
**Concept:** Privilege ceiling. A delegated administrator must never be able to grant more than they hold, or act on someone ranked above them. Otherwise any lower admin permission is a full admin permission.
**Failure story:** An admin creates a "Team Lead" role with `roles.manage` so leads can tidy roles. A lead deletes "Team Lead" with `?reassignTo=<Administrator>`; everyone in it, including them, is now admin. Or an "HR" role with `users.manage` changes the real admin's email and password, locking the owner out and taking every employee's time data and exports.
**Fix options:** (1) S — only `me.isAdmin` may assign the Administrator role (create, patch, reassign) or modify/reset/deactivate an admin; non-admins can't edit their own role or grant permissions they lack. (2) S — put these in one helper (P1) and call it from all five handlers. (3) M — add an audit log of privileged actions (L-level finding) so misuse is visible.
**Discussion question:** "How would you stop a user who can manage users from making themselves an admin?" — and in this app, should `users.manage` holders be able to touch admin accounts at all?

### H2 — WITHDRAWN 2026-11-05
The owner confirmed Bitsclock is a separate system from JMTS and does not hold JMTS customer or internal data, so the JMTS data-residency policy does not apply. The auditor's brief had wrongly assumed Bitsclock was a JMTS system. If Bitsclock ever stores JMTS data, this finding comes back. Original text kept below for history.

#### (withdrawn) H2 [HIGH] [High] [L] [Security/compliance] Data stored and processed outside JMTS-approved ecosystems
**Where:** `.env` keys `DATABASE_URL`/`DIRECT_URL` (Supabase), `UPSTASH_REDIS_REST_*`, `SMTP_HOST`; planned Vercel deploy; `.env.example` suggests Upstash free tier and Gmail/Brevo/Resend.
**What:** Employee names, emails, password hashes, IPs/user agents and work-time records sit in Supabase; cached session rows (with password hashes, see M8) go to Upstash; Vercel would process all of it.
**Concept:** Data residency. JMTS policy keeps sensitive internal data inside M365, SharePoint, the JMTS Azure tenant, or approved internal hosting. This is a policy finding regardless of code quality.
**Failure story:** Real employee data lands in accounts IT doesn't control: no IT access control, logging, retention or offboarding; the person who owns the Supabase/Upstash account leaving takes the data's custody with them.
**Fix options (JMTS policy):** (1) L — move into the JMTS Azure tenant: Azure Database for PostgreSQL (Prisma unchanged), App Service or Container Apps (single instance makes the memory cache/rate-limit fallback correct), no Redis or Azure Cache for Redis in the tenant (kv.ts would need a TCP client), mail via the JMTS M365 tenant. Coordinate with JMTS IT. (2) S, interim — keep only synthetic data on Supabase, don't deploy to Vercel, remove the Upstash/Gmail/Brevo/Resend suggestions from `.env.example`.
**Discussion question:** "Where does each piece of personal data in your system physically live, and who can access it?"

### H3 [HIGH] [High] [M] [Scale/correctness] Detailed report and CSV/PDF export silently stop at 2,000 rows
**Where:** `src/lib/reports.ts:68,131` (`take: ENTRY_LIMIT`), `src/app/api/reports/export/route.ts:11,15`; also entry list `src/lib/entries.ts` `take: opts.limit ?? 2000` (M15).
**What:** Totals come from GROUP BY over all rows; the row list is capped. Export writes `report.entries` with no truncation flag.
**Concept:** Data leaving the system for billing must be complete or visibly marked partial.
**Failure story:** 12 people × 8 entries × 21 days > 2,000. A company-wide monthly detailed CSV is already short; the invoice is built from it; the KPI total on screen disagrees with the sum of the file and nobody knows why.
**Fix options:** (1) M — stream the export with a keyset cursor `(startTime desc, id desc)` in 1,000-row pages; `withEntries: false` for summary export. (2) S, interim — return `truncated` and refuse detailed export above the cap with a clear message; banner in UI and PDF.
**Discussion question:** "Your API returns at most N rows. How does the caller know there are more?"

### H4 [HIGH] [High] [S] [Reliability/security] Security resets are separate writes; a failure leaves the attacker's sessions alive
**Where:** `src/app/api/auth/reset/route.ts:29-34`; `src/app/api/users/[id]/reset-password/route.ts:25-26`; `src/app/api/users/[id]/route.ts:39-53`; `src/app/api/auth/password/route.ts`.
**What:** `user.update({passwordHash, tokenVersion++})` → `consumeResetCode` → `revokeAllSessions` as three awaits. `tokenVersion` only kills access JWTs; refresh mints a fresh one for any unrevoked refresh session.
**Concept:** Atomicity. A security action is all-or-nothing, or it's not a security action.
**Failure story:** A user resets a stolen account. The password commits, then `revokeAllSessions` hits a pool timeout. The user sees an error; the attacker's refresh cookie keeps working; the code wasn't consumed, so the user's retry says "code incorrect". Two concurrent submits of the right code both pass.
**Fix options:** (1) S — one `prisma.$transaction([...])`: user update, `refreshSession.updateMany({revokedAt})`, and `passwordReset.updateMany({where:{id, usedAt:null}})` aborting if count is 0. (2) S — also a `sessionsValidAfter` timestamp on User checked during refresh, so one write invalidates everything.
**Discussion question:** "If your server crashes between line 32 and line 34, what state is the account in?"

### H5 [HIGH] [Medium] [S] [Security] Seed creates accounts with passwords written in the source, no environment guard
**Where:** `prisma/seed.ts:14-16` (admin password fallback; fixed demo password), demo Manager `sara@bitsclock.com` with report view-all/export.
**Concept:** Default credentials. Anything in the repo is public to everyone who ever sees it.
**Failure story:** Dev and prod share the one Supabase database, or someone seeds with prod env. A Manager login with a known password exists in production and can export the whole team.
**Fix options:** (1) S — refuse to seed demo users unless `SEED_DEMO=1` and not production; require `SEED_ADMIN_PASSWORD` with no fallback. (2) S — separate dev/prod databases; delete `@bitsclock.com` demo users from any DB that will hold real data. *Needs checking:* has the seed already run on the DB that will go live?
**Discussion question:** "What stops your demo data from reaching production?"

### H6 [HIGH] [Medium] [S] [Scale] Per-IP sign-in limit locks out an office behind one NAT
**Where:** `src/app/api/auth/login/route.ts:28` (`limit: 20, windowMs: 15 min` per IP); `src/app/api/auth/refresh/route.ts:19,34` (60/min); `opts.limit` overrides the `RATE_LIMIT_*` env vars.
**Concept:** Rate-limit keys must match who you're limiting. One public IP = whole office.
**Failure story:** 9:00, 25 colleagues open laptops after 12 h sessions expired; the 21st gets 429 for 15 minutes.
**Fix options:** (1) S — make login/refresh IP limits env-driven and much higher (~300), or key as IP+email; brute force is already covered by the per-account limit (8/15 min, `login/route.ts:16`). (2) S — fix the in-memory sweep bug (M2) so per-account limits are real.
**Discussion question:** "What's the difference between limiting per IP, per account, and per IP+account, and what does each protect?"

### H7 [HIGH] [High] [S] [UX/a11y] Modals yank focus back to the first control on every parent re-render
**Where:** `src/components/ui.tsx:155-167` (effect deps `[open, onClose]` + `first?.focus()`); callers pass inline `onClose` (e.g. `TeamView.tsx:350`); React Compiler not enabled. TrackerView re-renders every second while a timer runs.
**Concept:** Effects re-run when any dependency identity changes; an inline arrow is a new function every render. WCAG 3.2.2 / 2.4.3.
**Failure story:** With a timer running, an employee opens Edit entry; the cursor jumps to Description every second. Admin typing a job title in Add member snaps back to Full name (*needs a one-minute manual check* for forms whose state lives in the parent).
**Fix options:** (1) S — keep `onClose` in a ref, run the effect on `[open]` only, restore focus on close. (2) S — prefer `[autofocus]` / first text input over first button.
**Discussion question:** "Why does an effect with a function in its dependency array re-run, and how do you stop it?"

### H8 [HIGH] [High] [S] [UX/a11y] Focus indicator nearly invisible on fields, selects and search
**Where:** `src/app/globals.css:117-122` (`.field:focus`), `:316-317` (`.search:focus-within`); `Select.tsx:180`; `TrackerView.tsx:290` (`outline-none`, nothing replaces it).
**Concept:** WCAG 2.4.7 / 1.4.11 — focus must be visible at ≥3:1. A 25% sage halo is ~1.3:1 on white.
**Fix:** S — `box-shadow: 0 0 0 2px #fff, 0 0 0 4px var(--color-brand-600)` on focus, `focus-visible:ring-2 ring-brand-600` on Select triggers. Keeps the design language.
**Discussion question:** "How does a keyboard user know where they are on your Reports filters?"

### H9 [HIGH] [Medium — needs checking] [S] [UX/a11y] Row "⋮" menus likely unreachable by keyboard
**Where:** `src/components/RowMenu.tsx` (focus effect runs before the portal mounts; menu at end of `<body>`; arrows handled only on the menu).
**Impact:** Edit/Delete entry, Edit project, Reset password, Deactivate exist only in this menu. Verify with Tab/Enter in Chrome.
**Fix:** S — focus the first item after positioning; ArrowDown/Enter on the trigger; close on Tab and return focus.

### H10 [HIGH] [High] [M] [Dependencies] Prisma 6 leaves support 2026-11-19; Node 24.19 misses the Oct 2026 security release
**Where:** `package.json` (`prisma`/`@prisma/client` 6.19.3; no `engines` pin; local Node 24.19.0).
**What (sources fetched 2026-11-05):** Prisma 6 security-patch window ends 2026-11-19 (prisma.io/docs/orm/release-status). Node 24.22.1+ fixes 4 High CVEs incl. TLS hostname bypass and a zlib OOB write (nodejs.org/en/blog/vulnerability/october-2026-security-releases); another Node security release is pre-announced for 2026-11-11.

## Medium (one line each; detail on request)

## Looks good (from all agents)
- Every route goes through `requireUser`/`requirePermission`; entry ownership or `time.manage_all` checked on edit, delete, stop, bulk delete; `parseReportQuery` forces own scope; cache keys include user id.
- No SQL injection: all `$queryRaw` uses `Prisma.sql`/`Prisma.join` bound params, tz included; timezone bucketing correct for `timestamp(3)`.
- Sessions: HS256 pinned, issuer/typ checked; 256-bit refresh tokens stored hashed and rotated; tokenVersion bumped on password change, reset, deactivation; httpOnly/Secure/SameSite=Lax; same-origin check on mutations; `safeNextPath` blocks open redirects.
- Reset codes: CSPRNG, HMAC-stored, 15-min expiry, single use, reissue invalidates old; login uses a dummy hash for equal timing.
- `.strict()` zod everywhere, 64 KB body cap, explicit update fields (no mass assignment), HTML-escaped emails, no `dangerouslySetInnerHTML`; CSP with frame-ancestors none, HSTS, nosniff.
- `pg_advisory_xact_lock` inside a transaction (correct for the transaction pooler) serialises timer/overlap/bulk per user; overlap and single-timer re-checked inside the lock.
- Aggregates in SQL with good composite indexes; recharts and jspdf lazy-loaded; ETag + private Cache-Control; in-flight load de-duplication; no server polling for the timer.
- Client: timeouts, jittered GET retries, single shared refresh; offline/slow banners; teaching empty states; correct autocomplete attributes; labelled icon buttons; confirmations with clear consequences; Ctrl+K search, Enter starts timer, next-slot prefill.
- `tsc --noEmit` clean under `strict`; one `any` in all of src; comments explain why.

## Test plan (from test strategist)
Runner: Vitest (node) + Playwright; test DB is a dedicated Postgres with synthetic data in an approved environment (local container or JMTS Azure tenant), never Supabase. No rollback-per-test (withUserLock opens its own transaction): truncate between files, unique-user factories, serial files. Mock `next/headers` cookies; set Origin/Host; raise rate limits in test env; fake only `Date`.

1. Manual entry range and overlap (boundary values: touching, 1 ms overlap, exactly 24 h, 24 h+1 ms, now+60 s/61 s).
2. Timer state transitions (start→stop, double start, parallel starts → 1 created, other-user stop, >24 h rule).
3. Report scoping decision table (view_own / view_all × userId).
4. Aggregation and timezone buckets on real Postgres (Kolkata, New York DST, +14, invalid tz, billable sum, midnight-crossing rule).
5. CSV export completeness (2,000 vs 2,001) and escaping (quotes, newlines, leading `=`).
6. Refresh rotation and invalidation (2-min rotate, 89/91 s grace, parallel rotations, revoked, inactive).
7. Idempotency (replay, concurrent same key, handler throws, 5xx not stored, cross-route).
8. Role/user admin decision table (incl. H1 escalation cases → 403, parallel last-admin).
9. Forgot/reset (consume once, 5th wrong locks, 15 min boundary, parallel correct submits).
10. Unit: `time.ts` `periodRange`, `parseTimeText` under TZ=UTC and America/New_York.

Smoke suite (<2 min): login → me 200; start/stop → entry listed; overlap → 409; employee `userId=all` → 403; fixed-seed Kolkata report totals; refresh after rotation keeps session; CSV rows = totals; reset code works once.
